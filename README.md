# Road Intersection

Симуляция регулируемого перекрёстка в реальном времени на Rust и SDL2.

Приложение моделирует четыре въездные полосы, неизменяемые случайные маршруты, безопасное следование машин, адаптивные светофоры, защиту от starvation, анимированные BMP-спрайты и детерминированное движение с фиксированным timestep.

## 🚀 Быстрый запуск

### Требования

- Rust toolchain с Cargo
- Windows x64, Linux или macOS
- системный пакет SDL2 для Linux и macOS

Для Windows x64 runtime и import library SDL2 уже включены в репозиторий.

### Клонирование и запуск

```bash
git clone https://01.tomorrow-school.ai/git/nyestaye/road_intersection
cd road_intersection
cargo run --release
```

### Linux

```bash
sudo apt update
sudo apt install libsdl2-dev
cargo run --release
```

### macOS

```bash
brew install sdl2
cargo run --release
```

CMake, SDL2_image, SDL2_ttf и SDL2_gfx не требуются.

По умолчанию renderer использует VSync. Для проверки ограниченного fallback-режима
можно установить `ROAD_INTERSECTION_FORCE_RENDER_FALLBACK=1`.

## 🎮 Управление

| Клавиша | Действие                                 |
|---------|------------------------------------------|
| `↑`     | создать машину с юга                     |
| `↓`     | создать машину с севера                  |
| `←`     | создать машину с востока                 |
| `→`     | создать машину с запада                  |
| `R`     | создать машину со случайного направления |
| `Space` | пауза / продолжить                       |
| `Backspace` | сбросить симуляцию                  |
| `Esc`   | закрыть симуляцию                        |

Крестовина, `R`, `Pause` и `Reset` на боковой панели также работают мышью.

Каждая машина при создании получает один случайный неизменяемый маршрут:

- прямо;
- налево;
- направо.

Системный autorepeat игнорируется. Запрос на создание также отклоняется, если у въезда нет безопасного места или полоса достигла рассчитанной вместимости.

## 📝 О проекте

Road Intersection является SDL2-симуляцией перекрёстка двух дорог с четырьмя направлениями движения.

Состояние симуляции отделено от рендеринга. Движение машин, прогресс по маршруту, безопасная дистанция, вместимость очереди, фазы светофоров, занятость конфликтной зоны и fairness обновляются внутри детерминированной модели с фиксированным timestep. Renderer только читает полученное состояние и отображает сцену.

Контроллер использует консервативную схему: одновременно зелёный сигнал получает только одно въездное направление. После каждой зелёной фазы включается all-red, и только после очистки перекрёстка разрешается следующий поток.

## ✨ Возможности

### Дороги и маршруты

- две пересекающиеся дороги;
- одна въездная и одна выездная полоса в каждом направлении;
- маршруты прямо, налево и направо;
- неизменяемый выбор маршрута при создании;
- отдельные conflict entry и conflict exit для каждого пути;
- плавное изменение heading по polyline- и arc-маршрутам.

### Автомобили

- единая фиксированная скорость;
- явный lifecycle:
  - `Approaching`;
  - `Waiting`;
  - `Committed`;
  - `Crossing`;
  - `Leaving`;
- остановка перед stop line на красный;
- завершение проезда независимо от сигнала после входа в conflict zone;
- минимальная дистанция `CAR_LEN + GAP`;
- безопасная блокировка spawn;
- отдельный цвет и строка sprite sheet для каждого маршрута;
- два кадра визуальной анимации;
- автоматическое удаление и учёт проехавших машин.

### Светофоры

- красный и зелёный сигналы;
- одно активное въездное направление;
- all-red clearing;
- минимальное и максимальное время зелёного;
- учёт динамической вместимости полосы;
- приоритет критической очереди;
- приоритет overdue-направления;
- выбор максимального времени ожидания;
- round-robin при равенстве;
- защита от starvation.

### Интерфейс

- индикаторы заполнения очередей;
- визуализация capacity;
- текущая фаза светофоров;
- счётчики созданных, проехавших и находящихся на дороге машин;
- подсказка управления;
- постоянная легенда цветов маршрутов.

```text
keyboard input

|    Sim      |
|-------------|
| vehicles    |
| paths       |
| queues      |
| lights      |
| statistics  |
+-------------+
      |
      | fixed update 60 Hz
      v
+-------------+
|  Renderer   |
|-------------|
| roads       |
| markings    |
| BMP sprites |
| side panel  |
+-------------+
      |
      v
 SDL2 window
```

Симуляция использует фиксированный timestep:

```text
60 обновлений на одну модельную секунду
```

Renderer может вызываться чаще, но движение модели и visual tick изменяются только вместе с simulation step. Справа от сцены находится пассивная информационная панель: активный сигнал, очереди и capacity, легенда маршрутов, статистика и управление. Панель только читает состояние `Sim`.

## 🚦 Управление светофорами

Контроллер использует последовательность:

```text
одно зелёное направление
          |
          v
    all-red clearing
          |
          v
следующее зелёное направление
```

Зелёная фаза продолжается не меньше минимального времени. Для критической очереди она может быть продлена, но при наличии другого ожидающего направления завершается после максимального времени.

Следующее направление выбирается по классам приоритета:

1. overdue-очереди;
2. критические очереди;
3. максимальное время ожидания;
4. round-robin при равенстве.

Направление становится overdue после 15 модельных секунд ожидания. Предыдущий поток не выбирается повторно, пока существует другая непустая очередь.

All-red завершается только когда:

- прошло минимальное время clearing;
- в conflict zone не осталось машин.

### Вместимость полосы

Capacity рассчитывается по формуле задания:

```text
capacity = floor(lane_length / (vehicle_length + safety_gap))
```

При достижении capacity новая машина на этой полосе не создаётся.

## 🚗 Модель автомобиля

Каждая машина хранит:

```text
origin
route
progress
position
angle
phase
```

Маршрут случайно выбирается при создании машины и больше не меняется.

| Маршрут  | Цвет машины и легенды       |
|-----------|-----------------------------|
| Прямо    | фиолетовый (`#9971E4`)      |
| Налево   | оранжевый (`#F0A33A`)       |
| Направо  | бирюзовый (`#44C7B3`)       |

Движение рассчитывается по progress вдоль пути, а не по зависимому от FPS смещению пикселей. Position и heading определяются по выбранному Path на каждом фиксированном simulation step.

Следование обрабатывается от первой машины к последней отдельно для каждой въездной полосы. Машины на одном маршруте сохраняют дистанцию по progress, а после физического расхождения разных маршрутов освобождаются от ненужной взаимной зависимости.

## 🎨 Assets и рендеринг

Проект использует два BMP sprite sheet:

```text
assets/cars.bmp
assets/traffic_lights.bmp
```

`cars.bmp` имеет структуру `3 × 2`:

- три строки маршрутов;
- два кадра анимации на маршрут.

`traffic_lights.bmp` содержит два кадра:

- красный;
- зелёный.

Оба sheet используют chroma-key фон и загружаются средствами core SDL2. При запуске проверяются точные размеры. Отсутствующий, повреждённый или имеющий неверный размер asset завершает приложение с понятной ошибкой.

Боковая панель использует шрифт:

```text
assets/font.ttf
```

## 🧪 Тесты и CI

Полный набор локальных проверок:

```bash
cargo fmt -- --check
cargo test
cargo clippy --all-targets -- -D warnings
cargo build --release
```

Тесты проверяют:

- требуемое соответствие клавиш направлениям;
- остановку на красный;
- движение на зелёный;
- безопасную дистанцию;
- блокировку spawn-спама;
- неизменяемость маршрута;
- формулу capacity;
- удаление и учёт завершивших маршрут машин;
- очистку conflict zone;
- critical- и overdue-приоритет;
- round-robin fairness;
- отсутствие starvation;
- несколько детерминированных stress-прогонов по 60 секунд;
- отсутствие столкновений и переполнения очередей.

GitHub Actions выполняет:

### Ubuntu

```text
cargo fmt -- --check
cargo test
cargo clippy --all-targets -- -D warnings
cargo build --release
```

### Windows MSVC

```text
cargo test
cargo build --release
```

## ⚠️ Примечания

- Запускайте приложение из корня репозитория, чтобы относительные пути к assets оставались корректными.
- Windows x64 использует SDL2 из `vendor/sdl2`.
- Linux и macOS используют системную установку SDL2.
- Renderer не изменяет состояние симуляции.
- Анимация спрайтов является только визуальной и не влияет на скорость или логику светофоров.
- Контроллер отдаёт приоритет безопасности и fairness, а не максимальной пропускной способности.
